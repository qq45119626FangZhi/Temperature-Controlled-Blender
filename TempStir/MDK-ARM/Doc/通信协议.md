## 1. 一句话结论

板上**三条通信通道是并存的**（RS485/Modbus RTU、CAN、蓝牙 BLE 透传），不是三选一；它们共用**同一份"设备数据字典"**（一张寄存器表），各自有独立的物理接口与软件状态机，可以同时工作，也可以按需在配置里单独关闭某几条。协议上**以 Modbus RTU 为主协议**，蓝牙直接透传 Modbus 帧（复用同一套寄存器），CAN 作为可选的设备间总线后置实现。

## 2. 三条通道分别连什么设备、交换什么

| 通道 | 物理接口 | 对接设备 | 交换内容 | 角色 |
|---|---|---|---|---|
| **RS485 / Modbus RTU** | USART2（PA2/PA3）+ MAX13487E + 隔离 | PLC、触摸屏（HMI）、工控机、上位机软件（Modbus Poll / 组态王 / 自研 C#/Python 程序）、其它搅拌器组成的一主多从网络 | 读：实测温度/转速/剩余时间/状态/故障码；写：目标温度、目标转速、定时、启停命令、参数 | **从机（Slave）**，主站轮询 |
| **蓝牙 BLE（ECB01C 透传）** | UART4（PC10/PC11） | 手机 App、笔记本 BLE 调试工具（nRF Connect 等） | 与 Modbus 完全相同的寄存器语义（透传 Modbus 帧），外加 AT 命令做名称/查询 | 透传桥，手机侧当 Modbus 主站 |
| **CAN** | PA11/PA12 + TJA1050 | 另一块同型控制板、带 CAN 的工控设备、CAN 分析仪 | 固定 ID 的短帧：遥测（温度/转速/状态）、命令、心跳 | 节点（可选、后置） |

补充说明：

- **RS485 是"主推"通道**：设备在产线上通常挂在一台 PLC 或触摸屏下面，这是最通用的接法。
- **蓝牙是"手机调试/演示"通道**：不用接线，站在设备旁就能改参数、看曲线。ECB01C 是**透传芯片**（不是可编程 BLE 协议栈），MCU 只做串口收发 + AT 配置。
- **CAN 是"设备间"通道**：多台设备协同（例如一台主机控多台搅拌器）或接入车载/工控 CAN 网络，本项目暂无明确外部需求，**建议放到 P6 最后或干脆延后**。

## 3. "三种都能做吗？能切换吗？"

**能做，且是并存，不是硬件切换。** 依据：

- 三个外设互相独立：USART2、UART4、CAN 各自有引脚与中断，`.ioc` 里 **USART2(9600)、UART4(115200)、CAN(750k) 都已初始化**，`main.c` 里 `MX_UART4_Init()`、`MX_USART2_UART_Init()`、`MX_CAN_Init()` 都已调用，**不需要动 Core 的初始化**。
- 真正的"切换"发生在**软件层**：
  1. **通道使能位**：EEPROM 里存一个配置字节（如 `commEn = 0b101` = RS485+蓝牙开、CAN 关），上电按它决定创建哪些通道；默认三条全开。
  2. **命令仲裁**：三条通道都能写"目标转速/目标温度/启停"，必须规定优先级，避免互相打架。建议 **本地面板 > RS485 > 蓝牙 > CAN**（可用配置颠倒 RS485/蓝牙），低优先级源在**无按键操作超过 N 秒**后才允许写入。
  3. **读请求永不冲突**：R 类寄存器任何通道随时可读。

> 结论：不需要拨码开关或跳线；"只用某几种"通过配置位 + 是否插入对应模块（485 端子/天线/120Ω 终端电阻）来决定。

## 5. 统一数据模型（数据字典）

核心思想：**先定义设备数据，再定义各通道如何搬运这份数据**。这样"加一条通道"变成"加一个搬运器"，业务代码不用改。

- 所有对外可读写量都落在**一张保持寄存器表**（16 bit/寄存器，大端）；
- 温度单位 **0.1 ℃（有符号 int16）**，负温用补码；
- 转速单位 **RPM（有符号 int16，电机轴）**；
- 时间单位 **秒（uint16 或 int32 拆两寄存器）**；
- 状态/命令/故障码用 **bit 位定义**；
- 写操作统一进 `App_Comm` → 校验（范围/限温/故障）→ 调 `App_Motor*`/`App_Heat*` → 触发 EEPROM 静置落盘；
- 读操作从 `app_main_state`（互斥锁保护）+ 各模块 Get 接口取快照。

## 6. Modbus RTU（RS485）方案

### 6.1 通信参数（建议值，待确认 D1/D2）

| 项 | 值 | 备注 |
|---|---|---|
| 模式 | RTU 从机 | 不支持 ASCII |
| 波特率 | 9600（默认，可配 19200/38400/57600/115200） | 与 `.ioc` 一致；可配需存 EEPROM |
| 数据格式 | 8 数据位 / 无校验 / 1 停止位 | 现有 `.ioc` 配置 |
| 从机地址 | 1（1~247，可配） | 存 EEPROM |
| 响应超时 | t3.5 字符时间（由 FreeModbus porttimer 处理） | 已用 FreeRTOS 软件定时器实现 |
| 主站轮询周期 | 建议 200~500 ms | 从机不主动上报 |

### 6.2 支持的功能码

| 功能码 | 名称 | 用途 |
|---|---|---|
| 0x03 | Read Holding Registers | 读全部状态/参数（主用） |
| 0x06 | Write Single Register | 改单个参数/发单条命令 |
| 0x10 (16) | Write Multiple Registers | 一次下发多个参数 |
| 0x01/0x02/0x05/0x0F | 线圈类 | **本期不做**（无独立数字量，命令用 0x0007 位域） |

异常响应（**以实现为准**）：非法地址/只读寄存器 `02`、面板占用 `06` 从机忙、数值非法或被保护逻辑拒绝 `04`。
> 说明：FreeModbus 的参数校验异常默认映射为 `04`（`MB_EINVAL -> MB_EX_SLAVE_DEVICE_FAILURE`），本项目未改动第三方映射表，故数值非法统一返回 `04`，不再使用 `03`。

### 6.3 寄存器映射表（初版，待确认 D5）

地址按 `0x0000` 起，保持寄存器，读写属性 R / R/W：

| 地址 | 名称 | 类型/单位 | 属性 | 说明 |
|---|---|---|---|---|
| 0x0000 | 当前液温 | int16 / 0.1℃ | R | `App_TempReadCelsius(LIQUID)`，-32768=传感器异常 |
| 0x0001 | 目标液温 | int16 / 0.1℃ | R/W | 加热 PID 设定值，0=不加热 |
| 0x0002 | 当前转速 | int16 / RPM | R | 编码器实测（电机轴） |
| 0x0003 | 目标转速 | int16 / RPM | R/W | 写入即生效（软启动限斜率） |
| 0x0004 | 剩余时间 | uint16 / s | R | 运行倒计时 |
| 0x0005 | 系统状态 | uint16 位域 | R | 见 6.4 |
| 0x0006 | 故障码 | uint16 位域 | R | 见 6.5 |
| 0x0007 | 控制命令 | uint16 位域 | R/W | 见 6.6，写后自动清零 |
| 0x0008 | 铝板温度 | int16 / 0.1℃ | R | 风扇/限温判据 |
| 0x0009 | 加热占空比 | uint16 / % | R | 0~100 |
| 0x000A | 电机占空比 | uint16 / % | R | 0~100 |
| 0x000B | 设定时间 | uint16 / s | R/W | 定时时长，运行时改写=重新计时 |
| 0x000C | 风扇状态 | uint16 | R | 0=停 1=转 |
| 0x000D | 设备 ID 低 16 位 | uint16 | R | UID 哈希 |
| 0x000E | 设备 ID 高 16 位 | uint16 | R | |
| 0x000F | 固件版本 | uint16 | R | 高字节主版本，低字节次版本 |
| 0x0010 | 从机地址 | uint16 1~247 | R/W | 改后需重启生效，存 EEPROM |
| 0x0011 | 波特率代码 | uint16 0~4 | R/W | 0=9600 1=19200 2=38400 3=57600 4=115200 |
| 0x0012 | 累计运行时间低 16 位 | uint16 / s | R | 来自 `app_store` 统计 |
| 0x0013 | 累计运行时间高 16 位 | uint16 | R | |
| 0x0014 | 面板焦点项 | uint16 0~3 | R/W | 0=速度 1=铝板 2=液温 3=时间（让 App 箭头与 OLED 一致） |
| 0x0015 | 铝板上限温度 | uint16 ℃ | R/W | **默认 40**；0=不限制，否则必须 ≥35；1~34 非法，返回 04（见 6.9） |
| 0x0016~0x0017 | 保留 | — | R | 读 0 |
| 0x0018~0x001F | 预留（PID 增益 ×1000 等） | int16 | R/W | 本期只读或预留，等 D6 确认 |

> 说明：0x0000~0x0007 与现有 `app_modbus.h` 里已定义的枚举**语义一致**（只是把"当前温度"细化为"当前液温"），便于复用；新增项从 0x0008 往后追加，不破坏已有定义。

### 6.4 系统状态字（0x0005）

| 位 | 含义 |
|---|---|
| bit0 | 电机运行中（目标转速≠0） |
| bit1 | 加热输出中（占空比>0） |
| bit2 | 风扇运行中 |
| bit3 | 故障态（对应 0x0006 非 0） |
| bit4 | 定时计时中 |
| bit5 | RTC 有效（`App_RtcIsValid()`） |
| bit6 | 面板按键被操作（用于主站判断"本地占用"） |
| bit7 | 保留，写 0 |
| bit8 | 蓝牙已连接（模块上报 CONNECT OK） |
| bit9 | 液温已到目标，加热结束（P7 锁存；此时电机可能仍在转） |
| bit10~15 | 保留，写 0 |

### 6.5 故障码（0x0006）

| 位 | 含义 | 来源 |
|---|---|---|
| bit0 | 加热硬件故障（HEAT_FAULT_N 锁存） | `App_HeatIsFault()` |
| bit1 | 加热过流 | `App_HeatIsOverCurrent()` |
| bit2 | 液体 NTC 断线/短路 | `App_TempIsBroken(LIQUID)` |
| bit3 | 铝板 NTC 断线/短路 | `App_TempIsBroken(BOARD)` |
| bit4 | 铝板限温触发 | `s_plateLimited` |
| bit5 | 电机堵转（P7 实现后启用） | 待 P7 |
| bit6 | EEPROM 异常 | `App_StoreIsReady()==0` |
| bit7 | RTC 掉电丢时（OSF） | `App_RtcWasAutoInit()` |
| bit8~15 | 保留 | |

### 6.6 控制命令字（0x0007）

写 1 触发，执行后寄存器自动清零（读回 0），避免重复执行：

| 位 | 命令 | 行为 |
|---|---|---|
| bit0 | 启动 | 等价面板 KEY4 启动：目标转速=0x0003 值、定时=0x000B，开始计时 |
| bit1 | 停止 | 停机（清目标转速、停止计时） |
| bit2 | 清故障 | 调 `Int_GpioFaultReset()` + 清报警（仅当故障源已消失） |
| bit3 | 保存参数 | 立即把当前参数写 EEPROM（不等 2s 静置） |
| bit4 | 恢复默认 | 参数回出厂值（需 bit3 再保存） |

> 保护约束（2026-11-04 修订）：**电机启动只被电机类故障拦**（bit5 堵转，P7 启用）；加热类故障 bit0~bit4（含铝板限温 0x0010）、EEPROM bit6、RTC 丢时 bit7 **不再阻止电机启动**，返回码仍为 04 的只剩"命令字含未定义位"和"电机类故障"。加热保护由 `App_HeatControlStep()` 独立执行（板温到限即关加热，回差 2.0℃ 恢复），与电机互不牵连。目标温度/转速超范围（转速 0~500 rpm、液温 0~100.0℃）返回异常码 04。

### 6.7 报文示例（9600 8N1，RTU，CRC16/MODBUS 低字节在前）

**主站读 0x0000 起 8 个寄存器（状态快照）**
```
请求：01 03 00 00 00 08 44 0C           (从机1, 功能码03, 起始0x0000, 数量8, CRC)
响应：01 03 10 <16字节数据> <CRC>        (0x10=16 字节)
```

**主站写目标转速 300 rpm 到 0x0003**
```
请求：01 06 00 03 01 2C 39 F4          (0x012C = 300)
响应：原样返回（0x06 正常回显）
```

**主站写启动命令到 0x0007**
```
请求：01 06 00 07 00 01 <CRC>          (bit0=1)
```

**从机异常响应（地址越界）**
```
响应：01 83 02 <CRC>                    (功能码|0x80, 异常码 02)
```

> CRC 由协议栈自动计算，上位机侧 Modbus Poll/mbpoll 自动处理，手算可用在线 CRC16/MODBUS 工具核对。

### 6.8 实现要点（改造点）

1. `free_modbus/port/portserial.c`：`huart4` → `huart2`（含 `App_FreeModbusSerialRxCpltCallback()` 里的 `UART4` 判断）。
2. `app_comm.c` 实现 `HAL_UART_RxCpltCallback()`：按 `huart->Instance` 分流到 Modbus / 蓝牙，各自重启单字节接收（`HAL_UART_Receive_IT`）。
3. `app_modbus.c`：`App_MbSyncFromApp()`（eMBPoll 前刷读寄存器）与 `App_MbApplyWrites()`（处理 0x0001/0x0003/0x0007/0x000B/0x0010/0x0011 的写入），中间经过范围校验与保护判断。
4. 通信任务 `COMM`：优先级 `APP_TASK_PRIO_3`，栈 `APP_TASK_STACK_4X`，循环 `eMBPoll()`（内部阻塞等事件），与 UI 任务同优先级不抢占控制环（CTRL=PRIO_5）。
5. EEPROM：从机地址/波特率/通道使能位需要新增字段 → **`app_store` 需要 v2→v3 升级**（保留双槽+CRC 结构，加字段与迁移）。这是本方案唯一涉及存储结构变更的地方，待 D8 确认。

### 6.9 铝板限温规则（2026-11-04 修订，防"永久停热"）

- 限温判据：板温 `0x0008` ≥ 上限 `0x0015` → 锁存并强制关加热；板温 ≤ 上限 − 2.0℃ 才解除（回差防 600ms 节奏通断）。
- **非法配置防护**：上限取值域 = `{0}`（不限制）∪ `[35, 120]℃`。
  - 通信写 `0x0015`：0 或 ≥35 接受；1~34 拒绝并返回 `01 86 04`（原因：室温就可能贴着上限，锁存后永远降不到「上限−2℃」以下，加热会被永久关断）。
  - 面板调节：从 0 加一档直接跳 35，从 35 减一档直接回 0，中间值选不到。
  - 上电恢复：EEPROM 里若存着 1~34℃ 的旧非法值，自动按 0（不限制）处理，打印 `[P9] stored plate limit .. invalid -> no limit` 并回写 EEPROM。
- **清故障**：`0x0007` bit2 现在同时清除加热硬件锁存与铝板限温锁存（旧版清不掉限温锁存）；板温仍超高时会在下一个 600ms 控制周期重新锁存，属正常保护。
- 电机启动不再受 `0x0010` 影响（见 6.6 修订）。

### 6.10 液温到温完成（P7，2026-11-05）

- **判据**：目标液温 `0x0001 > 0`，且「本次目标下发后曾低于目标」（保证真的加热过）之后液温 ≥ 目标 → 判定完成。
  上电时液体本来就高于目标不触发。
- **动作**：关闭加热（`0x0009` 归 0）、锁存完成状态、蜂鸣器**长鸣 1 s**、状态字 `0x0005` **bit9 置位**；**电机不停**（搅拌继续），面板 UI 与倒计时不变。
- **解除**：修改目标液温（面板/通信）或调用 `App_HeatClearDone()`；解除后重新按 PID 加热。
- 通信侧表现：读 `0x0005` 可见 bit1（加热）清 0、bit9 置位；`0x0006` 故障码不变（完成不是故障）。

## 7. 蓝牙方案（ECB01C 透传）

### 7.1 定位

ECB01C 是**蓝牙转串口透传芯片**，MCU 侧只看到一串 UART 字节流：未连接时有 AT 命令语义，连接后基本是纯透传。因此**推荐让蓝牙直接透传 Modbus RTU 帧**——手机端当 Modbus 主站，帧格式、寄存器表与 RS485 完全一致，只写一套协议。

### 7.2 透传帧格式（推荐 A 案）

| 方案 | 说明 | 评价 |
|---|---|---|
| **A. 透传 Modbus RTU 帧（推荐）** | 手机 App 内置 Modbus 主站，收发与 RS485 同构 | 一份协议两端通用；调试工具现成（如 "Modbus Tools" 类 App） |
| B. 自定义二进制/文本帧 | 例：`$R,0x0002*CS\r\n` | 手机端更好写 UI，但要另立协议、另测 |
| C. 两者并存 | 连接后先识别首字节（0x01~0xF7 视为 Modbus） | 增加复杂度，暂不推荐 |

**关键约束：未设 MTU 时单包最大 20 字节** → 一次最多读 **7 个寄存器**（响应 5 + 2×7 = 19 字节）；手机端把 MTU 设为 247 后单包可达 244 字节（约 119 个寄存器），可整表读取。两次发送间隔 **≥100 ms**。

### 7.3 连接与状态

- 芯片在连接/断开时主动输出 `CONNECT OK\r\n` / `DISCONNECT\r\n`，MCU 解析后置"蓝牙在线"标志（可映射到 0x0005 bit8，预留）。
- 手机 3 分钟无数据会被芯片主动断开；MCU 侧超时 5s 无帧即认为空闲（不影响本地运行）。
- `STA` 引脚可选（未连接低/高阻、已连接高），需配下拉输入——目前 `Int_bsp_pins.h` **未定义**该引脚，本期用字符串解析即可，不接 `STA`。

### 7.4 AT 命令（仅出厂/调试用）

- 格式 `AT...\r\n`，芯片**先回显再返回结果**；非 AT 数据直接透传。
- 常用：`AT`→`OK`、`AT+VER?`、`AT+NAME?`/`AT+NAME=X`、`AT+MAC?`、`AT+LINK?`、`AT+MTU?`、`AT+RST`、`AT+DISC`。
- 名称最多改 10 次、MAC 最多改 3 次 → **禁止运行时反复写**；量产前用上位机一次性烧名字。
- 建议：`AT+NAME=TempStir-<设备ID后两位>`，UUID 固定 服务 `FFF0` / Notify `FFF1` / 写 `FFF2`。

### 7.5 分流规则（`app_ble.c`）

UART4 收到字节后：
1. 若在**未连接**状态且以 `AT` 开头 → 进 AT 解析器；
2. 否则一律进 Modbus 帧解析（复用同一套寄存器，等于"第二个 Modbus 通道"）；
3. 连接态收到 `CONNECT OK`/`DISCONNECT` 字符串时更新在线标志并丢弃该帧。

## 8. CAN 方案（可选，建议后置）

- 物理：TJA1050，250k/500k/750k 可选（`.ioc` 当前 750k，需与总线其他节点一致，待 D4）。
- 帧规划（标准帧，11 位 ID，数据 8 字节）：

| CAN ID | 方向 | 内容 |
|---|---|---|
| 0x180 | 设备→总线 | 遥测：液温(2B)、板温(2B)、转速(2B)、状态字(2B)，周期 100 ms |
| 0x200 | 总线→设备 | 命令：目标转速(2B)、目标温度(2B)、命令位(2B)、保留(2B) |
| 0x700+节点号 | 设备→总线 | 心跳（1 Hz） |
| 0x7FF | 广播 | 复位/紧急停止 |

- **阻塞点 G3**：CAN RX 中断优先级需从 0 改到 ≥5 才能用 FreeRTOS 队列；否则只能在 ISR 里写裸环形缓冲。
- 结论：**本期先不做**，等有明确对接设备再启用；`app_can.c/.h` 留空壳或直接延后。

## 9. 通道共存与命令仲裁

```
面板按键 ─┐
RS485 ────┼─→ App_Comm（命令入口 + 仲裁 + 范围校验 + 保护联锁）─→ App_Motor / App_Heat / app_store
蓝牙 ─────┤
CAN ──────┘
```

- **写命令统一入口**：任何通道的"改参数/启停"都必须走 `App_Comm`，禁止直接调用 `App_MotorSetTargetRpm()`。
- **仲裁优先级**（默认，可配）：面板 > RS485 > 蓝牙 > CAN。
  - 面板优先靠"最近 N 秒有按键"判断（N 建议 5~10 s），期间通信写命令被拒绝并返回异常码 06（从机忙）。
- **保护联锁**：故障态、NTC 异常、限温锁存时，启停/加热类命令一律拒绝（异常码 04）。
- **一致性**：读快照在 `app_main_state` 互斥锁内复制,避免读到半更新值。


连接与收发：
1. 扫描设备，找名字 **`BT_ECB1A6B01BA2`**（以**服务 UUID FFF0** 为准；**不要用手机系统蓝牙去"配对"**，该模块不配对，系统会提示"配对失败"）。
2. 连接后展开该服务：
   - **FFF1（Notify）**：点订阅（三个箭头图标），否则收不到应答；
   - **FFF2（Write）**：发送通道，写入类型选 *No response*。
3. 在 FFF2 里以 **Byte Array / HEX** 方式粘贴下表帧 → Send，FFF1 会收到应答。

帧表（从机地址 1，单位：温度 0.1℃ / 转速 RPM / 时间 s）：

| 功能 | 帧（HEX） |
|---|---|
| 读 0x0000~0x0006（液温、目标液温、转速、目标转速、剩余、状态、故障） | `01 03 00 00 00 07 04 08` |
| 读 0x0007~0x000D（命令=0、板温、加热%、电机%、设定时间、风扇、ID 低） | `01 03 00 07 00 07 B5 C9` |
| 读 0x000E~0x000F（ID 高、版本） | `01 03 00 0E 00 02 A5 C8` |
| 写目标转速 300 rpm | `01 06 00 03 01 2C 79 87` |
| 写目标液温 40.0℃（=400） | `01 06 00 01 01 90 D9 F6` |
| 写定时 60 s | `01 06 00 0B 00 3C F8 19` |
| 启动（bit0） | `01 06 00 07 00 01 F9 CB` |
| 停止（bit1） | `01 06 00 07 00 02 B9 CA` |
| 清故障 + 立即保存（bit2|bit3） | `01 06 00 07 00 0C 38 0E` |

应答示例（读 7 个寄存器）：`01 03 0E <14 字节数据> <CRC>`；写单个为原样回显 8 字节；失败为 `01 86 <异常码> <CRC>`（02 地址非法 / 04 数值非法或保护拒绝 / 06 面板占用）。

限制：未设 MTU 时 BLE 单包 ≤20 字节，所以上表一次只读 7 个寄存器（应答 19 字节）；手机端把 MTU 提到 247 后可整表读取。

与面板的关系：蓝牙写入走 `Menu_UiComm*` 桥，**等同于在面板上改设定**——OLED 会同步变化、参数会落盘；但它不是"远程按键"，无法操作校时页/焦点切换。面板有按键动作后 **8 s 内**所有蓝牙写入会返回 06。

## 13-C. V1~V4 实测步骤（手机 nRF Connect）

**准备**：连 `BT_ECB1A6B01BA2` → 进服务 FFF0 → **FFF1 点订阅（三个箭头，必做）** → FFF2 按 HEX 发送（No response）。发送前 8s 内不要动设备面板键，否则一律回 06。所有应答在 FFF1 里以 HEX 查看。

**V1 读（03，含 0x10 报文校验见 V2）**

| 发送帧 | 期望应答长度 | 数据含义 |
|---|---|---|
| `01 03 00 00 00 07 04 08` | 19 B | 液温/目标液温/实测转速/目标转速/剩余秒/状态字/故障码 |
| `01 03 00 07 00 07 B5 C9` | 19 B | 命令(恒0)/板温/加热%/电机%/设定时间/风扇/ID低 |
| `01 03 00 0E 00 02 A5 C8` | 7 B | ID高/固件版本（高字节主、低字节次） |
| `01 03 00 10 00 04 45 CC` | 11 B | 从机地址/波特率代码/累计运行低/高 |

判定：读回的液温、目标转速、设定时间与 OLED 显示一致；实测转速需电机运行才非 0；状态字 bit0=电机、bit1=加热、bit2=风扇、bit3=故障、bit4=计时、bit5=RTC 有效、bit6=面板刚操作、bit8=蓝牙在线。

**V2 写（06 / 10）**

| 发送帧 | 期望应答 | 面板/串口侧表现 |
|---|---|---|
| `01 06 00 03 01 2C 79 87` | 原样回显 | Speed 设定=300 |
| `01 06 00 01 01 2C D8 47` | 原样回显 | Liquid=30（30.0℃），加热开始出力 |
| `01 06 00 0B 00 3C F8 19` | 原样回显 | Time=60 |
| `01 10 00 03 00 02 04 01 2C 00 3C 73 9E` | `01 10 00 03 00 02 <CRC>` | 一条帧同时写转速300+定时60 |
| `01 06 00 07 00 01 F9 CB` | 原样回显 | Motor=Running、倒计时启动；读 0x0007 回 0 |
| `01 06 00 07 00 02 B9 CA` | 原样回显 | 停机 |
| `01 06 00 07 00 0C 38 0E` | 原样回显 | 清故障 + 立即落盘；断电重启后参数保持 |

**V3 异常码**

| 发送帧 | 期望应答 |
|---|---|
| `01 06 00 03 03 20 78 E2`（800>500 rpm） | `01 86 04 <CRC>` |
| `01 06 00 01 04 B0 DB 7E`（1200>1000=120℃） | `01 86 04 <CRC>` |
| `01 06 00 11 00 05 19 CC`（波特率码 5） | `01 86 04 <CRC>` |
| `01 06 00 07 00 01 F9 CB`（故障态下启动） | `01 86 04 <CRC>` |
| `01 06 00 02 00 01 E9 CA`（0x0002 只读） | `01 86 02 <CRC>` |
| `01 06 00 04 00 00 C8 0B`（0x0004 只读） | `01 86 02 <CRC>` |
| `01 06 00 14 00 00 C9 CE`（未定义地址） | `01 86 02 <CRC>` |
| 先按设备面板任一键，8s 内发 `01 06 00 03 01 2C 79 87` | `01 86 06 <CRC>`；等 8s 后重发 → 正常回显 |

**V4 单包 20 字节**

| 发送帧 | 应答长度 | 默认 MTU(23) 下 | MTU=247 后 |
|---|---|---|---|
| `01 03 00 00 00 07 04 08` | 19 B | 正常 | 正常 |
| `01 03 00 00 00 08 44 0C` | 21 B | 超 20 B，FFF1 无响应/被截断 | 正常 |
| `01 03 00 00 00 10 44 06` | 37 B | 失败 | 正常 |
| `01 03 00 00 00 20 44 12` | 69 B | 失败 | 正常 |

MTU 设置：nRF Connect 连接页右上角 ⋮/MTU 按钮 → Request MTU 247，状态栏显示 247 后再发。若模块始终不协商 MTU，记录为"受 20 字节限制"，按 ≤7 寄存器读取为准。
