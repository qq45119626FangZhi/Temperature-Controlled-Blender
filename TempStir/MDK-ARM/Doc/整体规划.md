> 依据：`MDK-ARM/Doc/SCH_主控_2_2026-08-27new.pdf`（原理图 V1.0，A4，1 页，嘉立创 EDA）

## 1. 产品与功能目标

智能温控搅拌机，核心功能：

1. **温度采集与闭环加热**：板载 NTC + 液体 NTC 双路测温，PWM 驱动加热组件，PID 控温，过温/断线/过流保护。
2. **搅拌电机调速**：编码器测速 + PWM 调速闭环，软启动、限幅、堵转保护。
3. **人机界面**：0.96" OLED（SSD1315，128×64）+ 4 按键，多级菜单设置目标温度/转速/时间。
4. **参数与时间**：M24C02 EEPROM 保存参数；DS3231 RTC 提供实时时间与秒中断。
5. **提示与散热**：蜂鸣器（PWM 4kHz，短鸣/长鸣/告警音）；风扇按温度阈值启停。
6. **通信**：RS485 Modbus RTU（从机）、CAN、蓝牙（UART4）三选/并存。
7. **故障与保护**：硬件故障锁存（74LVC1G74）读取与复位、故障停机与告警。

## 5. FreeRTOS 任务与同步设计

> 优先级用枚举 `APP_TASK_PRIO_1..5`；栈用 `APP_TASK_STACK_*`（128 字基础，默认 2 倍=256 字）。`configMAX_PRIORITIES=7`。

| 任务 | 职责 | 优先级 | 栈 | 周期/触发 | 同步 |
|---|---|---|---|---|---|
| 温度采集 | ADC→温度→滤波 | 4 | 2x | 100ms | 写全局状态（锁/队列） |
| 加热控制 | PID→PWM | 5 | 2x | 100ms | 读状态、写 PWM |
| 电机控制 | 编码器测速→PID→PWM | 5 | 2x | 20~50ms | 读编码器、写 PWM |
| 故障监控 | 读 HEAT_FAULT_N、过温/过流 | 5 | 2x | 50ms | 触发保护/告警 |
| UI/按键 | 扫描按键、刷新 OLED | 3 | 4x | 20/50ms | 队列：按键事件 |
| 通信 | Modbus/CAN/蓝牙收发 | 3 | 4x | 事件驱动 | 队列/任务通知 |
| 存储 | 参数保存（低频） | 2 | 2x | 事件/定时 | 队列 |
| 蜂鸣器/提示 | 短鸣/长鸣/告警音 | 2 | 2x | 事件 | 软件定时器 |
| 风扇 | 阈值启停 | 3 | 1x | 500ms | 读温度 |
| Timer Service | FreeRTOS 软件定时器 | 2 | 2x（configMINIMAL*2） | 内核 | — |
| IDLE | 空闲 | 0 | — | — | 可挂低功耗/看门狗喂狗 |

**同步机制**
- 互斥锁 `app_main_state_mutex`：保护 `App_State_t`（已有）。
- 队列：按键事件、UI 事件、通信帧、存储请求。
- 任务通知：DS_INT（RTC 秒中断）等轻量事件。
- 软件定时器：蜂鸣器短鸣、UI 刷新、超时。
- 事件组/信号量：按需（如"参数已变更"）。

**中断约束**
- ISR 只做：置标志、发队列、任务通知、清中断；禁止 printf、阻塞 HAL、解析。
- 调用 `...FromISR()` 的中断，其抢占优先级数值必须 ≥5（`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY=5`）。
- DS_INT（EXTI15_10）已定为 6；LSM_INT1/INT2（EXTI4/EXTI9_5）若用 FromISR 需确认优先级 ≥5。

## 7. 关键机制与控制策略

### 7.1 温度与加热
- NTC 采集：ADC→电压→查表/Steinhart-Hart→温度；滑动平均/中值滤波；断线/短路判定。
- 控温：目标温度 vs 当前温度 → PID → 加热 PWM（TIM2_CH1，PA0，**20kHz**）；带积分限幅、输出限幅、抗饱和。
- 加热 PWM 频率：CubeMX 原为 PSC=71/ARR=999 → **1kHz**，正好在人耳最敏感频段，24V 加热组件/线束在开关时发出明显“低鸣”（实测定位：按下加热通道即出现、关闭即消失）。现改为 PSC=0/ARR=3599 → **20kHz**（与电机 PWM 同频，超出听觉范围）；`.ioc` 已同步，`Int_TimInit()` 中另做一次强制校正，防止重新生成代码后回退。
- 保护：过温、升温异常、传感器故障 → 立即关加热、进入 FAULT、蜂鸣器告警。
- 电流：HEAT_I_ADC 监测加热电流（INA199），过流保护。

### 7.2 搅拌电机
- 测速：TIM3 编码器（PB4/PB5），定时计算 RPM。
- 调速：PID → TIM4_CH3 PWM（PB8，20kHz）；PB9 固定低（否则反转/刹车）。
- 保护：堵转（转速长期为 0 且占空比高）、过流、软启动（占空比斜坡）。

### 7.3 风扇
- 按温度滞回启停：**已实现 ≥35.0℃ 开、≤32.0℃ 关（回差 3℃），并强制两次切换间隔 ≥5s**；MOTOR_ON 高有效。
- 修改背景：原实现为单一门限 30.0℃（只有 5s 时间回差、无温度回差），板子自热即可越过门限，导致温度在 30℃ 附近长期"开-关-开"循环。阈值随 NTC 标定完成后可再复核。

### 7.4 故障与锁存
- HEAT_FAULT_N（PC3，低有效）由 74LVC1G74 锁存；故障时关加热/电机、UI 告警、蜂鸣器。
- FAULT_RST_N（PC2，开漏）复位锁存；故障排除后手动/自动复位。

### 7.5 状态机（建议）
`IDLE → HEATING → STIRRING/RUNNING → DONE`，任一环节故障 → `FAULT`。
- 由 `App_SysState_t`（IDLE/RUNNING/FAULT）承载，扩展内部子状态。

## 9. 通信规划
### 9.1 Modbus RTU（主推，USART2/RS485）
- **决策 2 确认**：RS485 从机，**波特率 9600 8N1**（无校验、8 数据位、1 停止位）；从机地址建议 `1`（范围 1~247，具体值待定），后续存入 EEPROM。
- 协议栈：FreeModbus RTU（已引入，见 3.1）；**当前仅引入未激活**（决策 10）。启用时先把 port 层串口从 `huart4` 校正到 `huart2`。
- 寄存器映射（建议）：
  | 地址 | 内容 | 读写 |
  |---|---|---|
  | 0x0000 | 当前温度 | R |
  | 0x0001 | 目标温度 | R/W |
  | 0x0002 | 当前转速 | R |
  | 0x0003 | 目标转速 | R/W |
  | 0x0004 | 剩余时间 | R |
  | 0x0005 | 系统状态 | R |
  | 0x0006 | 故障码 | R |
  | 0x0007 | 控制命令（启动/停止/复位） | R/W |
- FreeModbus 移植：串口收（USART2 中断/空闲中断）→ 队列 → 协议栈；发送走 HAL。

### 9.2 CAN（可选）
- TJA1050，PA11/PA12；波特率待定；报文协议待定。

### 9.3 蓝牙 ECB01C（UART4，PC10/PC11）
> 依据 `Doc/ECB01C-TSSOP16蓝牙芯片技术手册V1.4.pdf`（决策 12 已确认参考）。**蓝牙转串口透传芯片**，非可编程 BLE 协议栈，MCU 只需 UART + 可选 GPIO。

**串口参数（硬件决定，非软件可改）**
- 固定 **8 数据位 / 无校验 / 1 停止位**；波特率由 **CFG1/CFG2/CFG3 引脚电平**决定（内部上拉，悬空=1）：

  | CFG1,2,3 | 波特率 | CFG1,2,3 | 波特率 |
  |---|---|---|---|
  | 111 | 115200 | 011 | 9600 |
  | 110 | 57600 | 010 | 14400 |
  | 101 | 38400 | 001 | 4800 |
  | 100 | 19200 | 000 | 2400 |

- 规划沿用工程现状 **115200 8N1**（对应 CFG=111，需核对板上电阻/原理图）；供电 1.8~3.6V（推荐 3.3V），XTAL 为 16MHz 10ppm 9pF 无源晶振（内部已有负载电容，**不要外接电容**）。

**AT 命令（配置/查询）**
- 格式：以 `AT` 开头、以 `\r\n`（`0x0D 0x0A`）结尾；芯片**先回显收到的内容，再返回结果**；非 AT 数据直接蓝牙透传。
- 常用：`AT`→`OK`（测试）、`AT+VER?`、`AT+MODEL?`（`ECB01C-TSSOP16`）、`AT+RST`、`AT+LINK?`（`OnLine`/`OffLine`）、`AT+NOTIFY?`（0/1 订阅状态）、`AT+MTU?`、`AT+DISC`、`AT+NAME?`/`AT+NAME=X`（最多改 10 次）、`AT+MAC?`/`AT+MAC=X`（最多改 3 次）。
- 名称/ MAC 修改次数有限，**仅适合出厂配置，禁止运行时反复写**。

**透传行为与约束**
- 只有手机端**开启 Notify 订阅**（`+NOTIFY:1`）后，串口数据才透传给手机；芯片**不能主动开启订阅**。
- 连接成功 TXD 主动输出 `CONNECT OK\r\n`，断开输出 `DISCONNECT\r\n`（MCU 可解析作连接状态，比 STA 引脚更直接）。
- 每包最大：未设 MTU 时 **20 字节**、设 MTU 后 **244 字节**（MTU-3，MTU 可为 23/247，由手机端改）；**两次发送间隔 ≥100ms**（低波特率需更大）。
- 手机端 3 分钟无数据，芯片主动断开连接；`STA` 引脚（未连接低/高阻、已连接高）需 MCU 配**下拉输入**，可选使用。
- UUID：服务 `FFF0` / Notify `FFF1` / 写特征 `FFF2`；默认名称 `BT_XXXX...`。

**待办**：P6 阶段实现 `app_ble.c`（UART4 中断接收 + AT/透传分流 + 连接字串解析），具体命令协议（业务帧格式）决策 10 暂不展开。

## 10. 存储与时间
- M24C02（I2C2）：保存目标温度、PID 参数、校准系数、波特率/从机地址、运行统计；带版本号 + CRC，双备份。
  - **v2 布局**（结构体 92 字节，编译期校验 ≤ 96）：槽 0 = `0x40~0x9F`、槽 1 = `0xA0~0xFF`；每次写“非当前有效”槽并 `seq+1`，上电取 seq 较大的有效槽。
  - **字段**：magic/version/seq；UI 参数（speed/plateTemp/liquidTemp/runTimeSec）；PID 增益 ×1000 定点（motorPidKp/Ki/Kd、heatPidKp/Ki/Kd）；校准系数（encoderPpr、gearRatioX100、liquidOffsetC10、boardOffsetC10）；通信（modbusBaud、slaveAddr）；统计（totalRunSec、heatRunSec、motorStartCnt、bootCnt）；crc。
  - **v1→v2 迁移**：v2 两槽均无效时读取旧槽 `0x00/0x20`（28 字节，仅 UI 参数），保留 4 个 UI 值、其余填默认值，并立即回写 v2 到 `0xA0`（与旧槽不重叠，失败下次上电再迁移）。
  - **写入策略**：参数改动只置 pending，静置 `APP_STORE_SAVE_DELAY_MS`(2s) 后由 `App_StoreFlushSave()` 统一写一次；运行统计每 5 分钟批量落盘，电机停机时也触发一次。
  - **运行时镜像**：`App_StoreGet()` 取只读镜像，各模块用 `App_StoreSetUi/SetMotorPid/SetHeatPid/SetCalib/AddMotorStart/StatsTick` 更新，落盘时整体写入。
- DS3231（I2C2）：读写时间、秒中断（DS_INT/PC12）用于计时与 UI 刷新；掉电走时。驱动 `drv_ds3231`，App 封装 `app_rtc`。
  - **时间有效性**：读状态寄存器 0x0F 的 OSF（bit7）；`DS3231_SetTime()` 写完自动清 OSF。`App_RtcInit()` 发现 OSF=1（首次上电/换电池）时，用 `__DATE__/__TIME__` 的**编译时刻**兜底写入一次，保证上电即有可用走时基准。
  - **1Hz 秒节拍**：`DS3231_Enable1HzSqw()` 写控制寄存器 0x0E=0x00（INTCN=0、RS=00）→ INT/SQW 输出 1Hz；EXTI15_10(DS_INT) 中断调 `App_Main_NotifyFromISR()`，UI 任务用 `App_Main_AttachNotifyTask()` 挂接接收（仅置脏标记触发重绘）。**SQW 未接/未使能时系统仍按 40ms 轮询刷新，功能不受影响**；倒计时仍以 tick 为准（防止 SQW 丢失导致不能自动停机）。
  - **校时入口（主）**：面板 **长按 KEY1（≥600ms）** 进入校时页——KEY1 循环切 年/月/日/时/分/秒、KEY2/KEY3 增减（年 2000~2099、月 1~12、日按当月天数、24/60 循环）、KEY4 写入 RTC 并退出；星期由 `App_Rtc_Weekday()`（Sakamoto）自动推算。**日期必须可改**：只改时分秒会让日期永久停在固件编译日。不依赖串口 RX（**实测本机 USB 转串口只有 MCU→PC 方向**）。
  - **掉电诊断**：`App_RtcWasAutoInit()` 反映本次上电是否因 OSF=1 用编译时刻兜底初始化；启动日志会额外打印 `[P5] RTC time lost (OSF=1) -> init from build time, check battery`，用于判定纽扣电池是否失效。
  - **校时入口（备）**：串口 USART1 轮询命令（UI 任务内解析，不占用中断）：`time YYYY-MM-DD HH:MM:SS` 设置时间，单独 `time` 回读；RX 接线可用时方生效。编程入口为 `App_RtcSetTime()`。
  - **秒节拍自检**：1Hz 方波使能后若 5s 内无 DS_INT 中断，串口打印一次 `[P5] DS_INT no edge in 5s (sqw on), polling fallback`，刷新退化为 40ms 轮询（功能不受影响）。
  - 启动打印 `[P5] EEPROM=/DS3231=(含 valid/sqw)/PARAM=/CALIB=/STAT=` 便于验收。

### 13.1 IWDG 设计（决策 11，**已实现 2026-11-05**）
- **启用独立看门狗 IWDG**（LSI 约 40kHz），超时窗口建议 **1~2s**（需兼顾最慢控制任务周期）。
- **喂狗位置**：不放在各任务里各喂各的（易互相掩盖），而设一个**低优先级守护任务 `App_Main_WatchdogTask`**：
  - 各关键任务（温度、加热、电机、UI、通信、故障）周期性上报「心跳」标志位/计数；
  - 守护任务检查所有心跳都在时限内刷新 → 才调用 `HAL_IWDG_Refresh(&hiwdg)`；任一任务卡死则不喂狗，触发复位。
- **约束**：CubeMX 里启用 IWDG（`MX_IWDG_Init`，只改 USER CODE 之外的生成配置由 .ioc 管理）；调试期间可先用宏临时禁用，避免烧录/单步时反复复位。
- 与 FreeRTOS 配合：守护任务优先级设为最低（`APP_TASK_PRIO_1`），但不能被饿死；`configUSE_IDLE_HOOK` 亦可作补充喂狗点（不推荐单独用，无法检测任务卡死）。

**实际落地（2026-11-05，与上面方案的差异）**
- 工程未引入 HAL IWDG 模块（`stm32f1xx_hal_iwdg.c/h` 不在工程内，`HAL_IWDG_MODULE_ENABLED` 未开），因此 `app_fault.c` **直接写 IWDG 寄存器**：`KR=0xCCCC` 启动 → `KR=0x5555` 解锁 → `PR=3`（/64 → 625Hz）→ `RLR=1000`（≈1.6s）→ 等 `SR==0` → `KR=0xAAAA` 喂狗。这样**不必改 `Core/Src/main.c` 与 `.ioc`**。
- **启动时机**：不在 `App_Main_Init()` 里启动（OLED/EEPROM/RTC 探测 + printf 可能超过 1.6s，会立刻复位），改在 `WDG` 守护任务第一次运行时启动并先喂一次；上电另有 3s 心跳宽限窗口。
- **调试冻结**：启动前置 `DBGMCU->CR |= DBGMCU_CR_DBG_IWDG_STOP`，单步/下载时内核暂停则 IWDG 停止计数，避免烧录报 "Flash Download failed" 或单步乱跳。
- **心跳源**：`CTRL`（200ms）、`UI`（40ms）、`FAULT`（50ms）三个任务；**COMM 任务不参与**（`eMBPoll()` 阻塞在协议栈事件上，周期不可控，否则空闲也会被判卡死）。
- **任务**：`FAULT`（PRIO_4，50ms，故障聚合 + 加热类故障即时断电加热）、`WDG`（PRIO_1，100ms，心跳齐全才喂狗）。
- **临时关闭**：`app_fault.h` 里 `APP_IWDG_ENABLE` 改 0 重新编译即可（会打印 `[P7] IWDG disabled`）。

## 16. 2026-11-04 修复记录（加热 PWM 噪声 / 风扇回差 / 铝板限温回差）

**1. 板上间歇性“低鸣”定位与修复（已验收）**
- 现象：上电初始化、电机未启动即出现间断低鸣（持续约 3~5s，间隔约 100s）；与风扇无关（Plate 设 28℃、风扇不转时仍在响）。
- 定位：先做全静默固件（停三路 PWM + 引脚拉低 + 风扇锁定 + 不跑闭环）→ 噪声消失；再做面板按键逐路使能固件（KEY1 全静默 / KEY2 蜂鸣器 / KEY3 加热 / KEY4 电机）→ **KEY3 加热一开即复现，KEY1 关闭即消失**。
- 根因：加热 PWM 为 CubeMX 默认 PSC=71/ARR=999 → **1kHz**，正好落在人耳最敏感频段，24V 加热组件与线束在开关时发声；断续是因为温控 PID + 铝板限温让加热占空比间歇开关。
- 修复：加热 PWM 改为 PSC=0/ARR=3599 → **20kHz**（`Int_tim.c` 在启动 PWM 前强制校正，`.ioc` 已同步为 20kHz）。占空比按当前 ARR 动态换算，分辨率不变（3600 级）。
- 验收：静默 2 分钟无低鸣、电机运转 2 分钟无低鸣（用户实测 2026-11-04）。
- 风险提示：开关频率提高后 AO4184A 开关损耗上升，**需在实际加热工况下复核 Q4/U20 温升**；若温升偏高可降到 15kHz 或加 RC 缓冲。

**2. 风扇启停加温度回差**
- 原：单一门限 30.0℃，只有 5s 时间回差，板温贴门限会长期“开-关-开”。
- 现：`APP_FAN_PLATE_ON_C10=350`（≥35.0℃ 开）/ `APP_FAN_PLATE_OFF_C10=320`（≤32.0℃ 关），保留 5s 时间回差（`app_fan.c/.h`）。

**3. 铝板限温加 2℃ 回差**
- 原：`s_plateLimitC10` 无温度回差，板温贴限值时加热按 600ms 控制节奏断续通断。
- 现：触到上限锁存关断，降到「上限 − 2.0℃」以下才解除（`APP_HEAT_PLATE_LIMIT_HYST_C10=20`）；初始化或修改限值时清除锁存（`app_heat.c`）。

**4. 定位用测试代码已全部移除**
- `APP_BRINGUP_MODE` 宏及其静默输出 / 逐路使能实现（`App_Main_SilenceOutputs`、`App_Main_PinMode`、`App_Main_BringupApply`、`App_Main_BringupKeys`）全部删除，固件恢复正式业务逻辑（PID 闭环 + 风扇自动控制 + UI 任务）。
